## 一句话摘要

**dnsrelay** 是一台运行在你电脑上的 **DNS 代理程序**：局域网内的设备把 DNS 设成本机后，由它根据一份「域名 → IP」名单决定 **直接回答**、**拦截不良域名**，或 **向真实 DNS 服务器询问后再转回答案**；支持多台设备同时上网查询。

---

## 背景与目标

### 为什么做

课程要求实现符合 DNS 协议（RFC 1035）的 **UDP 域名解析服务**，体现 Socket 编程、协议解析、并发与超时处理，并能在 Windows 环境下与系统、`nslookup`、浏览器等配合使用。

### 产品目标

| 目标 | 说明 |
|------|------|
| **G1** | 按配置文件返回指定域名的 IPv4 地址（本地 DNS 能力） |
| **G2** | 对标记为 `0.0.0.0` 的域名返回「域名不存在」，用于拦截（不返回 0.0.0.0 这个 IP） |
| **G3** | 对名单中不存在的域名，代用户向 **上游 DNS** 查询并转回结果（中继） |
| **G4** | 支持多台电脑/多个应用 **同时查询**，且应答不会对错对象 |
| **G5** | 上游长时间无应答时程序仍稳定运行，不卡死、不占满 CPU |

### 怎样算「做完」（课程验收以 **Release 2** 为准）

- 本机与他机 DNS 指向本程序后，`nslookup` / `ping` / 浏览器域名访问正常。
- 配置文件中的测试域名（如 `test1`、`test0`、`www.bupt.cn`）行为符合下文功能描述。
- 能用 Wireshark 说明「查询如何被转发、ID 如何被改写」。

## 用户与使用场景

### 用户角色

| 角色 | 说明 | 关心什么 |
|------|------|----------|
| **局域网终端用户** | 将 DNS 设为运行 dnsrelay 的机器 | 上网、解析是否正确、是否被拦截 |
| **运维/实验者（你）** | 启动程序、编辑名单、指定上游 DNS | 命令行、日志、管理员权限 |
| **验收教师/助教** | 检查功能与答辩 | 三种行为是否清晰、并发与协议 |

### 典型场景

| 编号 | 场景 | 用户操作 | 期望结果 |
|------|------|----------|----------|
| **SC-01** | 访问校内/实验域名 | 访问 `www.bupt.cn` | 返回配置中的 IP，无需问上游 |
| **SC-02** | 拦截不良站 | 访问名单中 `0.0.0.0` 的域名 | 系统提示域名不存在，**不会**连到 0.0.0.0 |
| **SC-03** | 访问外网 | 访问不在名单中的域名 | 与直接问上游 DNS 结果一致 |
| **SC-04** | 宿舍多机上网 | 多台 PC DNS 指向本机 | 各查各的域名，互不串答 |
| **SC-05** | 上游故障 | 上游 DNS 不可达 | 程序不崩溃；客户端最终自行超时（本程序不伪造额外应答） |
| **SC-06** | 调试通路 | 仅验证「能转发」 | Release 1 下外网域名仍可解析（见发布计划） |

## 产品范围

### 本产品有（Release 2 完整交付）

- UDP/53 监听，供本机与局域网查询。
- 读取「域名 - IP」配置文件。
- 上述 G1～G5 行为。
- 命令行指定上游 DNS、配置文件、调试级别。

### 本产品不做（任何版本均不包含，除非另开文档）

- DNS over **TCP**、DNSSEC、完整 **EDNS 大报文**。
- 把缓存或查询结果 **写回** 配置文件。
- 使用第三方库实现哈希表等（须自研，见工程约束）。
- 替用户向上游 **自动重发** 查询（保持协议透明）。

### 后续版本（Release 3）

- 对中继得到的结果做 **内存 LRU 缓存**，减少重复向上游询问（加分项）。

## 功能需求

以下需求在 **Release 2** 必须全部满足；标注「R1」的仅 **Release 1** 需要。

---

### FR-01 启动与监听

**描述**  
程序启动后在本机 **UDP 53** 端口等待 DNS 查询，接受来自本机及局域网的数据包。

**验收标准**

- 管理员身份运行后，端口 53 处于监听状态。
- 他机将 DNS 设为运行程序的机器 IP 后，能向该程序发出查询（Wireshark 可见 UDP/53）。

---

### FR-02 读取域名名单（配置文件）

**描述**  
启动时（Release 2）从文本文件加载「IP + 域名」列表到内存；支持命令行指定路径，默认当前目录 `dnsrelay.txt`。

**文件格式**

- 每行一条：`IP地址` + 空白 + `域名`
- 示例见 [samples/dnsrelay-minimal.txt](../samples/dnsrelay-minimal.txt)
- 完整样例：[docs/guidance/dnsrelay-example.txt](./guidance/dnsrelay-example.txt)

**规则**

| 规则 | 说明 |
|------|------|
| 空行 | 忽略 |
| `#` 开头 | 视为注释，忽略（可选实现） |
| 重复域名 | **后出现的行覆盖前面的** |
| 域名大小写 | 统一按 **小写** 比较（`WWW.A.com` 与 `www.a.com` 视为同一域名） |
| 无效行 | 跳过并可在调试日志中记录；除非文件无法打开，否则不因此拒绝启动 |

**验收标准**

- 使用 minimal 样例：`test1` → `11.111.11.111`，`www.bupt.cn` → `123.127.134.10`。
- 加载完整 example 文件（约 900+ 行）后启动时间可接受，查询结果正确。

---

### FR-03 本地回答：返回配置的 IP（对应课程 Case 1）

**描述**  
当用户查询的域名在名单中，且 IP **不是** `0.0.0.0`，且查询类型为 **A 记录 / Internet 类** 时，程序 **自行构造 DNS 应答**，返回该 IPv4，**不再询问上游**。

**验收标准**

- `nslookup test1` 返回表中 IP。
- Wireshark 中 **无** 向上游转发的同名查询（本地直接响应）。
- 响应中 **权威位 AA = 0**（非权威应答）。

---

### FR-04 拦截：不良域名（对应课程 Case 2）

**描述**  
当域名在名单中且 IP 为 **`0.0.0.0`** 时，程序返回 **域名不存在**（DNS 响应码 NXDOMAIN），**不得** 在应答中返回地址 0.0.0.0。

**验收标准**

- `nslookup test0`（或任一 0.0.0.0 项）报「Non-existent domain」或等价错误。
- Wireshark 中应答 **RCODE = 3**，且 Answer 中 **无** A 记录 0.0.0.0。

---

### FR-05 中继：询问上游（对应课程 Case 3）

**描述**  
当域名 **不在** 名单中，或查询类型 **不是** A/Internet 时，程序将 **整份 DNS 查询报文** 转给上游 DNS，再将上游的应答转回 **发起查询的那台设备**。

**ID 映射（避免串答）**  
多台设备同时查询时，程序会为每条转发分配 **内部查询编号**，只修改报文头中的 **ID 字段** 发给上游；收到应答后再改回客户端原来的 ID。报文 **其余内容保持不变**。

**验收标准**

- 表外域名解析结果与「本机直接指定同一上游 DNS」一致。
- 两客户端同时查询时，各自得到与自己请求匹配的应答，无张冠李戴。
- Wireshark 可见：发往上游的 ID ≠ 客户端原始 ID，回客户端时 ID 已恢复。

---

### FR-06 非 A 类查询一律转发

**描述**  
例如 MX、AAAA、PTR 等查询，程序 **不查名单、不本地编造答案**，只做 FR-05 的中继。

**验收标准**

- `nslookup -type=MX` 某域名时，行为与直接问上游一致（由上游回答或拒绝）。

---

### FR-07 上游超时

**描述**  
若在上游等待超过约定时间（建议 **5 秒**，实现可为常量）仍无应答，程序 **放弃该次转发**，**不向客户端发送任何 DNS 包**。程序继续处理其他查询。

**验收标准**

- 上游 IP 故意不可达时，进程不退出、不长时间占满 CPU。
- 客户端表现为解析超时；程序在 `-d` 日志中可记录超时（若实现调试）。

---

### FR-08 报文大小限制

**描述**  
遵循传统 DNS over UDP **512 字节** 限制：超长入站包丢弃；本地生成的应答不超过 512 字节；上游响应超过 512 字节时不转给客户端。

**验收标准**

- 正常 `nslookup` 不受影响的条件下，程序对异常大包不崩溃。

---

### FR-09 命令行

**语法**

```text
dnsrelay [-d | -dd] [上游DNS的IP] [配置文件路径]
```

| 用法 | 行为 |
|------|------|
| `dnsrelay` | 静默；上游默认 `202.106.0.20`；配置文件默认 `dnsrelay.txt`（Release 2 起加载） |
| `dnsrelay -d …` | 输出简要日志：时间、序号、客户端 IP、查询域名等 |
| `dnsrelay -dd …` | 输出更详细的调试信息（含 ID 映射、包长等） |

**Release 1**  
可解析 `-d`/`-dd` 与上游地址；**不读取** 配置文件。

**验收标准**

- 帮助文档/PRD 与程序实际参数一致；非法参数有明确错误提示或说明。

---

### FR-10 内存缓存（Release 3）

**描述**  
对 **中继成功** 且可解析出的 A 记录结果，写入 **内存 LRU 缓存**；下次同一域名在缓存未过期时直接应答，无需再问上游。缓存 **不写入** 配置文件。

**查找顺序（Release 3）**  
配置文件 → 内存缓存 → 中继上游。

**验收标准**

- 同一表外域名连续查询两次：第二次 Wireshark 中无向上游的 DNS 请求。

## 发布计划

用 **用户可感知的能力** 划分版本；课程正式验收以 **Release 2** 为准。

### Release 1 —「仅转发」（调试版）

**用户能做什么**  
把本机 DNS 指向程序后，**所有** 域名查询都像直接问上游一样被转发并拿回结果；**还没有** 名单、拦截、本地回答。

**仍具备**  
多客户端并发、ID 映射、超时不上报、512 限制、调试日志。

**不具备**  
不读 `dnsrelay.txt`；不能演示 Case 1/2。

**用途**  
先用 Wireshark 确认「客户端 ↔ 本程序 ↔ 上游」通路正确，再开发 Release 2。

**课程验收**  
❌ 不算完成课设。

---

### Release 2 —「完整课设」（验收版）

**用户能做什么**  
完整实现 FR-01～FR-09：名单解析、本地回答、拦截、中继、并发、超时、他机访问。

**课程验收**  
✅ 以此为准。

---

### Release 3 —「加速查询」（扩展）

**用户能做什么**  
在 Release 2 基础上，重复访问同一域名的速度更快（命中内存缓存）。

**课程验收**  
加分 / 扩展，非最低要求。

## 术语表

| 术语 | 含义 |
|------|------|
| **DNS** | 域名系统，把域名翻译成 IP 地址 |
| **客户端** | 发起 DNS 查询的设备或程序（电脑、解析器） |
| **上游 DNS** | 程序转发查询时使用的真实 DNS 服务器（如校园 DNS） |
| **中继 / 转发** | 收到查询后转给上游，再把应答转回客户端 |
| **A 记录** | 域名对应的 IPv4 地址记录 |
| **NXDOMAIN** | 「域名不存在」的 DNS 错误应答 |
| **ID** | DNS 报文头中的 16 位编号，用于把应答和查询对应 |
| **UDP/53** | DNS 常用的传输方式（端口 53） |
| **512 字节** | 传统 DNS UDP 报文长度上限（未实现 EDNS 时） |
| **配置文件 / 名单** | `dnsrelay.txt`，存放域名与 IP 的对应关系 |
